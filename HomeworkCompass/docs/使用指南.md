## Part 1 · 交付了什么

### 1.1 仓库现状

```
HomeworkCompass/
├── pyproject.toml                  # 包元数据 + hw 入口 + pytest 配置
├── README.md                       # 一页速查
├── docs/superpowers/
│   ├── specs/2026-11-06-…-design.md      # 绑定规格（§5 校验层 / §6 排版 / §8 CLI / §11 DoD）
│   └── plans/2026-11-06-…-core.md        # 18 任务实施计划（含实测校准与偏差记录）
├── src/homework_compass/           # 2,431 行
└── tests/                          # 2,113 行，20 个文件，217 条测试
```

| 层 | 文件 | 职责 |
|---|---|---|
| 中枢 | `src/homework_compass/models.py` | 7 个数据结构 + 3 个枚举 + JSON 双向序列化（兼容 poc 旧格式） |
| | `src/homework_compass/errors.py` | 7 个异常，一 一对应退出码 |
| | `src/homework_compass/config.py` | 四级配置合并；**凭证不是配置字段** |

| 校验层 | `src/homework_compass/parsing/provenance.py` | 溯源引擎：5 级证据等级 + 字段策略 |
| | `src/homework_compass/parsing/segmentation.py` | 分段与噪声判定 |
| | `src/homework_compass/parsing/vocabulary.py` | 套话 / 连接词 / 高优信号三张词表 |
| | `src/homework_compass/parsing/validate.py` | 采信、降级、覆盖率、pending 组装、销账 |
| | `src/homework_compass/parsing/extract.py` | 抽取协议 + `LlmExtractor` / `NaiveExtractor` |
| 排版层 | `src/homework_compass/layout/skeleton.py` | 骨架坐标契约 + 生图提示词 |
| | `src/homework_compass/layout/fonts.py` | 字体解析 + 字形覆盖探针 |
| | `src/homework_compass/layout/compose.py` | 文字层排版（纯 Pillow 绘制，不含生图） |
| 编排 | `src/homework_compass/pipeline.py` | 对外 API，库只返回结构 |
| CLI | `src/homework_compass/cli/main.py` | 参数解析 + 退出码翻译 |
| | `src/homework_compass/cli/confirm.py` | 全项目唯一读 tty 的模块 |

依赖方向只有一条，已由测试锁住：`cli/ → pipeline → parsing.* / layout.* → models, errors`。

运行期依赖只有 `Pillow`，开发依赖只有 `pytest`，要求 Python ≥ 3.13。

### 1.2 三条不变量（产品行为的全部意义）

| 不变量 | 实现 | 违反时的后果 |
|---|---|---|
| **零杜撰** | 每个字段都溯源到原文；`ZERO_TOLERANCE` 字段（subject/quantity/requirements）无出处即丢弃并进 pending；`task` 仅允许动词补全 | 卡面上不会出现老师没说过的话 |
| **零遗漏** | 原文每一段未被数据承接 → `UNCOVERED` pending，带 `source_sentence` 与 `related_seq` | 不会静默吞掉一条作业 |
| **有歧义必拦** | `pending` 非空 → `render` 抛 `NeedsConfirmation`，一个字节都不写；OCR 来源强制追加确认项 | 宁可不出图，也不出错图 |

## Part 2 · 安装与 5 分钟跑通

```bash
cd /path/to/HomeworkCompass
python3 -m pip install -e ".[dev]"
```

### 最小闭环（不花钱、不联网）

```bash
# 1) 解析：--offline 走兜底解析器
hw parse --file tests/fixtures/raw1.txt --name 小宇 --offline --date 2026-11-06 --out /tmp/hw.json

export DASHSCOPE_API_KEY=sk-xxxx     # 这条必须，OCR 要用
hw parse --image hw_photo.jpg --name 小宇 --date 2026-11-06 --out hw3.json


# 2) 出图
hw render /tmp/hw.json --out /tmp/hw_out/
```

实际输出：

```
写入：/tmp/hw.json｜可出图 5 项｜待确认 0 项
成品：/tmp/hw_out/homework_2026-11-06_quest-map_dinosaur.png  (2480x3508 @300dpi)
！这是排版预览（占位底图），不是可打印成品。真实底图请用 --base。
排版无问题。
```

### 在线路径（会调用模型、会计费）

```bash
export DASHSCOPE_API_KEY=sk-xxxx          # 或写进当前目录 .env
hw parse --file tests/fixtures/raw2.txt --name 小宇 --date 2026-11-06 --out hw.json
hw confirm hw.json
hw render hw.json --out out/
```

> **注意（易踩）**：`--offline` 是**显式关闭**在线模型的开关。**不写** `--offline` 就会调用 `qwen-plus`，是要花钱的。
>
> `src/homework_compass/cli/main.py` 里 `pick_extractor` 的 docstring 写成「默认离线」，与代码和 README 都相反 —— 这是当前唯一一处**文档与行为不符**，行为以本文和 README 为准（代码：`if args.offline: return NaiveExtractor()`，否则返回 `LlmExtractor`）。

## Part 3 · 命令参考

| 命令 | 作用 | 花钱 |
|---|---|---|
| `hw parse` | 原文 / 文本 / 板书照片 → `hw.json` | `--offline` 时否 |
| `hw confirm` | 逐条处理 `pending`（只在 tty 交互） | 否 |
| `hw render` | `hw.json` → A4 300dpi PNG | 否 |
| `hw zones` | 打印骨架坐标契约 | 否 |
| `hw prompt` | 打印底图生图提示词（只打印，不调用） | 否 |

### 3.1 `hw parse`

输入三选一，互斥且必填：

| 参数 | 说明 |
|---|---|
| `--file PATH` | 读 UTF-8 文本文件 |
| `--text "…"` | 直接给原文 |
| `--image PATH` | 板书照片，先 OCR 再解析；**强制追加 `ocr_unverified` pending** |

| 可选参数 | 默认 | 说明 |
|---|---|---|
| `--name` | `""` | 孩子姓名，进卡面标题 |
| `--date` | 今天 | 进卡面与文件名；非 `[\w-]` 字符会被压成 `-` |
| `--offline` | 关 | 用 `NaiveExtractor`，不联网 |
| `--text-model` | `qwen-plus` | 覆盖配置 |
| `--ocr-model` | `qwen-vl-ocr` | 覆盖配置（与文本链路互不影响） |
| `--set N.FIELD=值` | 无 | 修正某字段，可重复 |
| `--resolve id或文本` | 无 | 声明某条 pending 不纳入图，可重复 |
| `--out` | `hw.json` | 落盘路径 |

`--set` 的字段白名单（唯一来源：`parsing/validate.py` 的 `EDITABLE_FIELDS`）：

```
subject  task  quantity  requirements  priority  type
priority ∈ {high, normal}      type ∈ {written, oral, reading, checkin, material}
```

`--resolve` 先按 id 精确匹配（形如 `unc-3f2a91c8`），失败再按归一化文本在 `pending.text` 与 `source_sentence` 里找，**必须恰好命中 1 条**，否则报错要求改用 id。这样家长不必抄 id，也不会因为「家长签字」同时出现在两条里而错销。

典型用法：

```bash
# 补要求进第 1 项 + 声明某条不是作业
hw parse --file raw.txt --name 小宇 --date 2026-11-06 \
  --set 1.requirements=家长签字 \
  --resolve 收到请回复 \
  --out hw.json
```

输出格式（有 pending 时）：

```
写入：hw.json｜可出图 3 项｜待确认 1 项
  ? [uncovered] 家长签字　（出自「1.数学：完成练习册P12-13，家长签字」）
```

**有 pending 仍然写盘并退出 3** —— 进度不丢，这是刻意的。

### 3.2 `hw confirm`

```bash
hw confirm hw.json
```

只有 4 个按键：

| 键 | 行为 |
|---|---|
| `d` | 不纳入图（`dismiss`），该条销账 |
| `e` | 补进某一项：依次问「第几项 → 字段 → 新值」，走 `pipeline.correct` |
| `s` | 跳过这条，保留 pending |
| `q` | 保存进度退出 |

非 tty（管道、CI、AI 助手）**拒绝交互**，输出结构化 JSON 且**不写盘**、退出 3：

```json
{
  "interactive": false,
  "hw": "hw.json",
  "pending": [
    {"id": "unc-3f2a91c8", "text": "家长签字", "reason": "uncovered",
     "source_sentence": "1.数学：完成练习册P12-13，家长签字", "related_seq": 1}
  ],
  "hint": "用 hw parse --set / --resolve 处理，或在终端里运行 hw confirm"
}
```

这个形态就是给「AI 助手对话调用」准备的：把 JSON 交给上游，上游决定后用 `--set/--resolve` 回写，不需要 tty。

`e` 路径的健壮性（都有回归测试）：字段不在白名单 → 打印白名单并跳过；序号处 EOF → 跳过而不是死循环；先 `e` 编辑后 `d` 销账 → 该 id 可能已被编辑解决，不算错误。

### 3.3 `hw render`

| 参数 | 默认 | 说明 |
|---|---|---|
| `--skeleton` | `quest-map` | 骨架；目前只有一款 |
| `--skin` | `dinosaur` | `dinosaur` / `space` / `ocean`（本版只影响 accent 色） |
| `--base PATH` | 无 | 本地 A4 底图；不传则用占位图 |
| `--panel-alpha` | `190` | 面板不透明度（0–255） |
| `--out DIR` | `out` | 输出目录（按调用时 cwd 解释） |

产物：`homework_{date}_{skeleton}_{skin}.png`，2480×3508 @300dpi。

- **`pending` 非空 → 退出 2，不写任何文件**（不是写了再删）。
- 作业项 > 6 条 → `LayoutError`，退出 4，提示换骨架或分页。
- 文字降档低于 14pt 下限或放不下 → 不静默截断，进 `issues` 并打印：

```bash
hw render hw.json --out out/
# 成品：out/homework_2026-11-06_quest-map_dinosaur.png  (2480x3508 @300dpi)
# 排版问题（不静默放行）：
#   ! [station-3] 已降到 12.0pt（低于 14.0pt 下限） —— …
```

`issues` 非空**不是错误**，退出码仍是 0 —— 它表示「字被缩小了，你可能想精简」。

**接真实底图**：底图上那 9 个区域必须内部纯白、无字无图，尺寸精确 2480×3508。用 `hw prompt` 的输出喂生图工具，出图后 `hw zones` 对照坐标，再 `--base` 上色。

**仓库自带一张可用的**：`assets/base_robot_quest-map.png`（可爱桌面机器人主题，2480×3508 @300dpi）。它的坐标不是估的——框位直接从 `quest-map` 骨架的 `Zone.rect` 读出来画，所以与文字层严丝合缝；九个框内部实测纯白（内缩后非白像素 0–1 个，来自圆角抗锯齿）。

```bash
hw render hw.json --base assets/base_robot_quest-map.png --out out/
```

生成脚本是仓库根目录的 `draw_robot_base.py`（一次性工具，不属于包）：换配色改顶部常量，换机器人位置改三处 `robot(x, y, scale)` 调用，重跑即重新生成。它只画装饰与空框，**不写字**——所有文字仍由 `compose` 绘制。

### 3.5 退出码与脚本化

| 码 | 含义 | 谁产生 |
|---|---|---|
| 0 | 成功 | 全部命令 |
| 2 | 有 pending，拒绝出图 | `render` |
| 3 | 解析 / 确认后仍有 pending | `parse`、`confirm` |
| 4 | 参数错误、字段白名单、坏 JSON、未知骨架、文件不存在、`LayoutError` | 全部 |
| 5 | API 错误、模型返回垃圾、字体错误 | `parse`、`render` |

`argparse` 原本的 `exit(2)` 被改写成 `ValueError` 再翻译成 4 —— 否则「拼错参数」会被脚本误读成「正常拒绘」。

推荐的分支写法：

```bash
hw parse --file raw.txt --out hw.json
case $? in
  0) hw render hw.json --out out/ ;;          # 干净，直接出图
  3) hw confirm hw.json;                     # 人（或 agent）处理 pending
     [ $? -eq 0 ] && hw render hw.json --out out/ ;;
  4) echo "参数/数据错了，别重试" >&2; exit 4 ;;
  5) echo "上游接口或字体坏了，别重试" >&2; exit 5 ;;
  2) echo "还有 pending" >&2; exit 2 ;;
esac
```

## Part 4 · 配置

优先级：**命令行 > 环境变量 > `config.toml` > `profile.toml` > 内置默认**（合并顺序见 `config.py` 的 `load_config`）。

| 键 | 默认 | 环境变量 |
|---|---|---|
| `name` | `""` | `HW_NAME` |
| `default_skeleton` | `quest-map` | `HW_SKELETON` |
| `default_skin` | `dinosaur` | `HW_SKIN` |
| `text_model` | `qwen-plus` | `HW_TEXT_MODEL` |
| `ocr_model` | `qwen-vl-ocr` | `HW_OCR_MODEL` |
| `fonts` | `()` | — |
| `out_dir` | `out` | `HW_OUT` |

`config.toml` / `profile.toml` 都从**当前目录**读取。示例：

```toml
# profile.toml —— 一次设置、长期复用
name = "小宇"
default_skeleton = "quest-map"
default_skin = "space"

# config.toml —— 机器相关
out_dir = "/Users/me/Desktop/homework"        # 建议写绝对路径
fonts = ["/System/Library/Fonts/Hiragino Sans GB.ttc"]
```

三条硬规则：

1. **不认识的键直接报错**（退出 4），并列出可用键 —— 打错字静默失效比报错更糟。
2. **类型校验**：`name = 123` 当场报错；`fonts = "/path/a.ttc"` 也报错（会被 `tuple()` 拆成一个个字符）。
3. **凭证不是配置字段**。`DASHSCOPE_API_KEY` 只能来自环境变量（或当前目录 `.env`，由 `load_dotenv_default` 灌进 `os.environ`，已存在的值不覆盖）。它不在 `Config` 里，任何一条「把 key 写进 toml」的路都走不通。

## Part 5 · 当库用

```python
from homework_compass import pipeline
from homework_compass.parsing.extract import NaiveExtractor

hw = pipeline.parse_homework(
    raw_text, extractor=NaiveExtractor(),
    date="2026-11-06", name="小宇",
)
# hw.items / hw.extras / hw.pending / hw.report 都是结构，不做 IO

for p in hw.pending:
    print(p.id, p.reason.value, p.text, p.related_seq)
#  unc-3f2a91c8 uncovered 家长签字 1

hw = pipeline.correct(hw, 1, "requirements", "家长签字")   # 增补，返回新对象
hw = pipeline.dismiss(hw, "unc-3f2a91c8")                  # 销账（只对真实存在且仍 pending 的 id）

pipeline.save_hw(hw, "hw.json")
result = pipeline.render(hw, skeleton="quest-map", skin="dinosaur",
                         out_dir="out", base=None, panel_alpha=190, fonts=())
# result.path / .width / .height / .dpi / .issues / .used_placeholder
```

`render` 在 `pending` 非空时抛 `NeedsConfirmation`；`>6` 项抛 `LayoutError`；字体不覆盖中文抛 `FontError`。库不认识 tty，也不打印任何东西。

### `hw.json` 结构

```json
{
  "date": "2026-11-06", "student_name": "小宇", "slogan": "",
  "items": [{
    "seq": 1, "subject": "数学", "task": "完成练习册", "quantity": "P12-13",
    "requirements": ["家长签字"], "requirements_all": ["家长签字"],
    "priority": "high", "priority_signals": ["签字"],
    "estimated_minutes": null, "type": "written",
    "provenance": {"subject": "verbatim", "task": "partial"}
  }],
  "extras": ["明天记得穿校服"],
  "pending": [{"id": "unc-3f2a91c8", "text": "彩泥", "reason": "uncovered",
               "source_sentence": "4.明天带美术材料：彩泥", "related_seq": 4}],
  "unresolved": ["彩泥"],
  "source_text": "…原文逐字…",
  "source_kind": "text",
  "report": {"traced": [], "advisories": [], "uncovered": [], "priority_overrides": [],
             "notes": [], "stats": {"auto_dropped_boilerplate": 2}}
}
```

- `requirements` 是**上图可见**的要求（已去掉与 `task` 重复的）；`requirements_all` 是全部采信要求，供优先级判定与审计。
- `unresolved` 是 `pending` 的文本投影，只写给旧工具消费；**读取时以 `pending` 为准**，两者不一致且都不空会直接报错。
- `source_text` 必须留着 —— 重跑校验要靠它。

## Part 6 · 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| `! 这是排版预览（占位底图）` | 没传 `--base` | 正常，对位用；要成品就传真底图 |
| 退出 2 | `pending` 非空 | `hw confirm` 或 `hw parse --set/--resolve` |
| 退出 3（parse 后） | 有遗漏 / 杜撰 / OCR 未核对 | 看 `? [reason] text（出自…）` 那几行 |
| 退出 4 且提示未知骨架 | `--skeleton` 拼错 | 目前只有 `quest-map` |
| 退出 4「作业项 N 条超过骨架留白 6 个」 | 单日作业 > 6 条 | 换骨架（待做）或拆两页 |
| 退出 5「字形覆盖探针失败」 | 字体不含中文 | `fonts` 指向含 CJK 的 ttc/ttf，或装系统字体 |
| 退出 5「接口/字体错误」 | key 无效、额度用尽、模型返回垃圾 | 检查 `DASHSCOPE_API_KEY`、余额；别重试同一请求 |
| 卡面某条要求没出现 | 它与 `task` 重复，按「不重复印」规则并入任务句 | 预期行为 |
| `LayoutError` 但项数只有 4 | 单条文字太长，降到 12pt 仍放不下 | 精简该条或 `--set` 改短 |

### 已知边界（本版不解决）

1. 关键词优先级仍是词表级近似：「明天开始练习」也会判高优 —— 宁可多标，不漏标。
2. `NaiveExtractor` 只按句拆条，`quantity`/`requirements` 恒空 —— 离线路径保证「能用」，不保证「好看」。
3. OCR 只有接口，没有用真实板书照片验证过；首次真图 OCR 必须人工比对。
4. 同一模型两次输出可能不同 —— 所有信任来自校验层，不来自模型的确定性。
5. 6 项以上作业抛 `LayoutError`，分页在 spec 之外。
6. 皮肤只影响 accent 色。本版实装 3 款（`dinosaur` / `space` / `ocean`），它们的视觉差异要等真实底图才看得出。
