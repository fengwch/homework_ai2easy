# 架构约束规范（AI-Agent）

本文从仓库实际架构与长期记忆库决策中提炼,作为 Claude Code 与协作者做架构相关改动时必须遵守的硬约束。"约束"意味着默认不可违反,确需突破者必须在 PR/记忆库中明确决策记录。

## 1. 服务定位与边界

### 1.1 本仓库职责

- **AI 能力提供方**:OCR 识别、个性化故事生成、解题引导、语音合成、插图生成、漫画分格等可被 HTTP 调用的 AI 服务。
- 通过单一 HTTP API 服务对外暴露;请求/响应契约与上游调用方(主后端)文档对齐。

### 1.2 不归本仓库

以下职责**禁止**在本仓库实现,出现即视为越权:

- 用户/儿童档案管理、鉴权与权限。
- 作业 CRUD、上传文件持久化、长期对象存储。
- 任务状态持久化(跨进程或跨服务的 job 队列、状态机)。
- 对外完整 REST 路径(版本前缀、网关聚合)由主后端统一编排,本仓库只提供被调用的子接口。
- 业务计费、推送通知、消息队列编排。

如需扩展上述职责,必须先在记忆库登记决策;默认应推回主后端。

## 2. 模块划分

### 2.1 顶层模块边界

按职责划分为以下并列模块,每个模块**单一职责、内聚高、对外通过明确入口暴露**:

| 模块类别 | 职责 |
|---|---|
| API 层 | FastAPI 应用、路由、中间件、请求/响应模型 |
| OCR 服务 | 图片 → 结构化题目 |
| 内容生成 | 故事生成、解题引导、插图提示词、插图图像、漫画分格 |
| 语音合成 | 文本 → 音频字节 |
| 营销发布 | 营销内容组装与第三方平台发布 |
| 工具 | OCR 不属于的视觉处理工具、第三方 MCP 容器配置 |
| 工具库 | 跨模块复用的环境加载、日志、通用工具 |
| 配置 | 服务级 YAML 配置与业务级 YAML/JSON 配置(分离两处管理) |
| 测试 | 单元、接口、端到端 |
| 文档与记忆 | 对外说明、长期记忆库 |

### 2.2 模块间依赖规则

- API 层**只依赖**服务模块,**不直接依赖**第三方 SDK。
- 服务模块之间**禁止互相调用业务函数**;若需要复用,把共用逻辑下沉到工具库或单独抽出公共子模块。
- 工具库**只依赖**标准库与第三方基础库;**禁止**反向依赖 API 层或服务模块。
- 配置文件**只被代码读取**,**不**被代码自动重写(除非是用户显式发布的运营日记之类副产物)。
- 测试目录可以依赖任意模块,但被测代码**不能依赖**测试目录。

### 2.3 模块内部分层

涉及流水线的模块(如 OCR、内容生成)采用**预处理 → 主处理 → 后处理**三段式:

- **预处理**:输入归一化、格式转换、参数校验。
- **主处理**:核心算法或外部模型调用。
- **后处理**:结构化、字段映射、与对外契约对齐。

每段独立目录或文件,对外暴露统一 service 入口;调用方**只看到** service 入口,不看到流水线细节。

### 2.4 禁止巨型单体

- 单文件**不应承载**多个独立职责;判断标准:是否能用一句话概括文件目的。
- 文件长度无硬性上限,但超过此长度时必须自检是否需要拆分:类、流水线阶段、第三方适配器各自成文件。
- 新增能力优先建子目录或子模块,不直接往现有大文件追加。

## 3. 接口定义

### 3.1 对外 HTTP 接口

- 唯一对外协议为 HTTP/JSON,通过 FastAPI 暴露;**禁止**直接暴露 gRPC、GraphQL、WebSocket 等其他协议(如有需要,需升级架构决策)。
- 路由路径按业务领域分组,使用名词复数或行为短语,版本前缀与网关层统一处理,本仓库默认不带版本号。
- 每个路由必须声明响应模型(response_model);请求体模型必填字段标必选,可选字段给默认值。
- 字段命名遵循"对外契约保持上下游约定的风格(常为驼峰),内部 Python 用蛇形",不得为统一风格擅自改对外字段名。
- 错误返回统一通过 HTTP 状态码 + 结构化错误体表达;状态码语义遵循:
  - 400:入参错误
  - 401/403:鉴权(主后端层面,本仓库一般不处理)
  - 404:资源不存在
  - 502:外部依赖失败(OCR 引擎、LLM、第三方 API 不可用)
  - 504:外部依赖超时
  - 500:未预期异常

### 3.2 模块间接口

- 服务模块对外只暴露**一个入口**(类或顶层函数);调用方**禁止**直接调用模块内部私有函数。
- 入口函数签名稳定:参数、返回结构变更视为破坏性变更,必须同步更新所有调用方与 API schema。
- 返回结构优先使用扁平 dict 或 dataclass,在 docstring 给出字段说明;复杂嵌套结构必须在记忆库或文档中描述。

### 3.3 入参与出参

- **入参严格校验、出参信任内部**:入口处对类型、范围、必填做防御;模块内部函数信任已校验的输入,不重复校验。
- 二进制数据(图片、音频)入参支持多种形式(base64 字符串、URL、字节、文件路径),由入口统一归一化为字节后传入流水线。
- 出参中包含 URL 时,**必须**指明是绝对 URL 还是相对路径,且在文档中标注前缀来源。

## 4. 数据流规范

### 4.1 主要数据流

- **OCR 流**:图片输入 → 预处理 → OCR 引擎 → 题目解析 → 结构化题目列表 + 截取的插图。
- **内容生成流**:儿童档案 + 题目列表 → 主题选择 → LLM 生成故事 → 派生插图提示与解题引导 → 与前端契约对齐的响应。
- **语音流**:文案 → 分批 → TTS 引擎 → 音频字节拼接 → base64 返回。
- **插图流**:提示词列表 + 兴趣 → Provider 选择 → 异步调用第三方 → 图像列表(URL 或 base64)。
- **营销发布流**:模板 + 素材 → 文案组装 → 合规检查 → 经第三方 MCP 发布 → 写运营日记。

### 4.2 数据转换规则

- **进入流水线后只在模块内部传递业务结构**;不允许把 HTTP 请求对象、FastAPI Request 透传到服务深处。
- 流水线各阶段**只信任**上一阶段的输出契约;变更上游字段必须同步下游与文档。
- 二进制大对象(图片、音频)以**字节**传递,在入口归一化、出口编码为 base64 或落盘后返回 URL,不在内部模块来回 base64 编解码。
- 对外暴露的存储路径由静态文件挂载或 CDN 地址承担,模块内部只生成相对路径或绝对路径,不直接拼接对外 URL。

### 4.3 异步与超时

- 所有 IO 密集调用(LLM、OCR API、TTS、插图生成)**必须**设置超时上限;超时通过 504 返回,而非无限等待。
- 长耗时请求(分钟级)在 API 层使用 async + 超时;**禁止**在事件循环上同步阻塞。
- 进程内并发使用 asyncio 与线程池;**禁止**自行起后台 Thread/Process 做隐式任务,改用主后端的任务队列。

### 4.4 副作用

- 文件落盘、日志写入等副作用**只在 service 内部**执行;路由层不直接读写文件系统。
- 落盘路径由配置控制,运行时按时间戳或 UUID 生成子目录,避免冲突。
- 网络副作用(发布、推送)**默认 dry-run**,真实执行需显式开关或参数;CLI 与定时任务尤其要遵守。

## 5. 技术选型限制

### 5.1 强制技术栈

| 类别 | 强制选型 |
|---|---|
| 语言版本 | 与 requirements.txt 锁定的 Python 版本一致 |
| Web 框架 | FastAPI(ASGI) |
| 生产服务器 | Gunicorn + Uvicorn Worker |
| 配置加载 | YAML + 环境变量 + 项目内提供的容错 dotenv 加载 |
| LLM 编排 | LangChain 1.0 + LCEL(Runnable 接口、管道符组合) |
| LLM 模型 | ChatTongyi/Qwen 系列(经 DashScope) |
| 嵌入模型 | DashScope 文本嵌入 |
| 向量库 | Milvus(如需) |
| 图像处理 | Pillow + OpenCV(headless) |
| 测试框架 | pytest + httpx + 标准库 mock |
| 日志 | 项目内统一日志模块(基于标准 logging) |

### 5.2 禁止使用

以下选型**禁止**新增,出现即视为架构违规:

- LangChain 旧版 Chain/run API(以及任何被 1.0 显式废弃的接口)。
- 直接 print 做日志、自行 basicConfig 配置 root handler。
- 在业务模块里调用 dotenv 的 load_dotenv;只允许在进程入口经容错加载函数加载一次。
- 在代码中硬编码任何密钥、第三方 endpoint、用户路径。
- 同步阻塞调用(time.sleep、阻塞 IO)放在 async 路由中。
- 全新引入与现有依赖功能重叠的库(如另一个 HTTP 框架、另一个 ORM、另一个日志库)。
- 直接暴露第三方 SDK 的数据结构到对外契约;必须经过 schema 转换。
- 在仓库根新增散文件;能力归入既有模块或新建子目录。

### 5.3 引入新依赖的门槛

- 新增第三方包**必须**:
  1. 与 LangChain 1.0 / 当前 Python 版本兼容。
  2. 替代既有能力时给出迁移路径与废弃计划。
  3. 在 PR 描述与记忆库注明动机、替代方案、风险。
- 仅用于一两处的工具优先选择标准库或现有依赖的子能力,**不为单点功能引入大依赖**。
- 商业 API 接入必须支持开关与降级:可选依赖缺失时不应让进程崩溃,而是返回明确错误或回退方案。

## 6. 配置与密钥管理

- 所有可调参数从 YAML 与环境变量读取;加载顺序:**配置文件默认值 → 环境变量覆盖**。
- 配置按用途分目录:服务级(模型、超时、引擎选择等)与业务级(营销活动、定时任务参数)分离,**禁止**互相迁移而不更新读取代码。
- 密钥**只**通过环境变量或外部秘钥管理服务注入;**禁止**进入仓库、日志、错误信息、对外响应。
- 新增环境变量必须更新示例配置文件并在 PR 中列出;读取代码必须对缺失值有兜底或抛出清晰错误。

## 7. 可观测性

- 每个对外路由经中间件记录方法、路径、状态码、耗时。
- 关键流程节点用 info 级日志,带结构化字段(如 questions_count、theme、duration_ms)。
- 异常使用 exception 或带 exc_info 的日志,**禁止**手动拼接 traceback 字符串。
- 不在日志中输出密钥、用户隐私字段、完整大图 base64;必要时只输出长度或摘要。
- 业务错误返回给调用方的 detail 字符串简洁可读,**不得**包含内部栈信息。

## 8. 长期记忆与决策记录

- 涉及架构、接口契约、技术选型、外部集成的改动**必须**同步更新记忆库的架构与进度文档。
- 重要技术选择写入决策日志:**问题、选项、决策、原因**四件套缺一不可。
- 临时性决策(如临时关掉某 provider)在决策日志中标注**生效条件与回退条件**,避免成为永久遗产。

## 9. 演进准则

当现有架构无法承载新需求时,按以下顺序考虑:

1. 在现有模块内扩展(加配置项、加 provider 适配)。
2. 拆分新子模块,保持原有入口契约不变。
3. 引入新模块类别,在记忆库登记并更新本约束文档。
4. 升级跨模块抽象(如服务总线、任务队列),需团队共识与决策记录。

**禁止**跳过这些步骤直接重写既有模块或大幅调整目录结构;所有架构性改动都需要可追溯的决策依据。
