## 关键决策点

1. **单仓库 AI 服务层，不碰业务与持久化**
   - **原因**：主后端已承担用户/儿童档案、作业 CRUD、文件持久化、计费推送。
   - **影响**：本仓库只做可被调用的 AI 原子能力；新增任务队列、状态机等需求必须推回主后端。

2. **自动发帖以 xiaohongshu-mcp 为主，开放平台为可选遗留**
   - **日期**：2026-03-28
   - **原因**：个人开发者通常不具备开放平台 `publish_note` 权限；mcp 方案通过 Docker 内 Chromium + 已登录 Cookie 绕过。
   - **影响**：`client.py` / `xhs_api.yaml` 不再作为默认路径；运维需关注 mcp 容器 Cookie 失效风险。

3. **API 入参只承载业务变量，运行参数走配置**
   - **日期**：2026-02-28（提交 `b2c8a9c`）
   - **原因**：减少调用方负担，避免运行时阈值频繁变更导致接口膨胀。
   - **影响**：`/content/illustrate` 仅接受 `illustration_prompts + interests`，其余由 `configs/content_generation.yaml` 提供。

4. **所有 IO 密集接口强制异步 + 可配置超时**
   - **日期**：2026-02-24（提交 `4365c0b`）
   - **原因**：插图生成、漫画分格耗时分钟级，同步阻塞会导致 worker 积压。
   - **影响**：超时返回 504，阈值由对应 YAML 控制；禁止在 async 路由内直接 `time.sleep` 或同步阻塞 IO。

5. **环境变量容错加载（safe_load_dotenv）**
   - **日期**：2026-02-08（提交 `c0c2506`）
   - **原因**：`.env` 单条解析失败不应导致整进程崩溃。
   - **影响**：进程入口统一调用 `safe_load_dotenv`；业务模块内禁止再次加载环境变量。

## 已知技术债务

- **端到端测试依赖真实凭据**
  - **影响范围**：`tests/test_e2e_homework_flow.py` 等真实链路测试在无 `DASHSCOPE_API_KEY` 时无法运行。
  - **建议**：CI 阶段接入凭据托管或拆分为标记为 `integration` 的独立 job，默认 pytest 不执行。

- **xiaohongshu-mcp 容器 Cookie 持久化依赖人工扫码**
  - **影响范围**：营销自动发帖链路；Cookie 过期后需重新登录。
  - **建议**：建立登录态监控与告警；探索 Cookie 刷新机制或兜底回退到手动发布。

- **配置目录双轨制（`configs/` vs `config/`）**
  - **影响范围**：新成员易将营销/业务配置误放入服务级目录，或反之。
  - **建议**：读取代码路径与目录命名已固化；新增配置时严格对照既有文件位置，迁移需同步所有读取方。

- **可选遗留开放平台代码仍在仓库**
  - **影响范围**：`marketing/xiaohongshu/client.py`、`config/xhs_api.yaml` 当前无活跃调用方。
  - **建议**：若长期不启用，在决策日志中标注废弃条件与删除时间线。

- **观测性局限于本地日志**
  - **影响范围**：当前仅 `logs/app.log` + 中间件耗时日志；上量后难以排查分布式问题。
  - **建议**：若流量增长，引入外部 APM 与结构化日志聚合，而非继续扩展本地文件日志。

## 开发注意事项

### 不要修改的约定

- **禁止直接暴露 gRPC / GraphQL / WebSocket**：对外唯一协议为 HTTP/JSON via FastAPI。
- **禁止巨型单体文件**：新增能力优先建子目录或子包，不往现有大文件追加。
- **禁止服务模块互相调用业务函数**：复用逻辑下沉到 `utils/` 或新建公共子模块。
- **禁止硬编码密钥、路径、第三方 endpoint**：全部走环境变量或 YAML。
- **禁止在业务模块内调用 `load_dotenv`**：仅进程入口加载一次。
- **禁止 print 做日志、自行 basicConfig**：统一通过 `utils.logging.get_logger` 获取 logger。
- **禁止 LangChain 旧版 Chain/run API**：项目锁定 LangChain 1.0 + LCEL（`|` 组合、`invoke`）。

### 必须遵守的规范

- **提交信息**：Conventional Commits（`type(scope): subject`），scope 与目录对齐，中英任选但推荐英文以便检索。
- **测试**：新增功能必须配套单元/接口测试；外部服务默认 mock；修复 Bug 先写失败测试再修。
- **接口变更**：必须声明 `response_model`；入参必填标必选、可选给默认值；字段命名对外保持原风格（常为驼峰），内部用蛇形。
- **配置变更**：新增环境变量同步 `.env.example`，并在 PR 描述列出；缺失字段读取代码需兜底。
- **架构/契约/集成变更**：同步更新 `memory-bank/` 中的架构与进度文档。

### 测试要求

- **命令**：
  - `pytest` — 跑全部测试（mock 部分不依赖凭据）。
  - `pytest tests/test_api_ocr.py` — 单文件。
  - `pytest tests/test_e2e_homework_flow.py -v -s` — 端到端（需凭据，加 `-s` 看步骤输出）。
- **mock 边界**：放在项目自有 service 入口，不 mock 第三方 SDK 内部细节。
- **启动检查**：提交前确认服务能启动、健康检查通过。
