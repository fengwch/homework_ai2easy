# 图片生成完整流程 - Coze 工作流说明

本文档描述从「故事生成」到「插图提示生成」再到「绘图 API 调用」的完整流程，包含各节点提示词与参数，便于在 Coze 中复现或导入。

---

## 一、流程总览

```
[输入] 儿童档案 + 题目列表
    ↓
┌─────────────────────────────────────────────────────────┐
│ 节点1：故事生成 (generate_story)                         │
│ 输入: child_profile, questions, subject                  │
│ 输出: story, theme, character_name, illustration_prompts  │
└─────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────┐
│ 节点2：插图提示生成 (generate_illustration_prompts)      │
│ 输入: story, theme, character_name                        │
│ 输出: illustration_prompts (多句描述列表)                 │
└─────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────┐
│ 节点3：英文绘图提示词优化 (LLM refine)                   │
│ 输入: raw_prompt + 配置(style/panels/include_dialogue等) │
│ 输出: refined_english_prompt                             │
└─────────────────────────────────────────────────────────┘
    ↓
┌─────────────────────────────────────────────────────────┐
│ 节点4：调用绘图 API (TTAPI Gemini / Midjourney)          │
│ 输入: refined_prompt, 配置(mode/aspect_ratio/refer_images)│
│ 输出: image_url 或 images 列表                           │
└─────────────────────────────────────────────────────────┘
    ↓
[输出] 插图 URL 列表
```

---

## 二、节点 1：故事生成

**作用**：根据儿童档案与题目生成个性化故事正文，并预生成插图提示（可选）。

### 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| child_profile | object | 含 name, age, grade, interests |
| questions | array | 题目列表，每项含 structuredData.stem 或 originalText |
| subject | string | 学科，默认 "数学" |

### 配置参数（来自 configs/content_generation.yaml）

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| story.min_chars | 300 | 故事最少字数 |
| story.max_chars | 500 | 故事最多字数 |
| story.default_theme | 小动物学习 | 未匹配兴趣时的主题 |
| illustration.panels_per_prompt | 3 | 配图组数 |
| illustration.panels_in_image | 6 | 每组几格 |
| illustration.panels_layout | "2x3" | 布局 |
| illustration.include_dialogue | true | 是否含对话框/旁白 |

### 提示词模板（完整）

```
你是一位儿童故事创作助手。请根据以下信息生成一个适合{{age}}岁儿童（{{grade}}）的短故事，将作业题目自然地融入故事情节。

故事主题：{{theme}}
主角姓名：{{character_name}}
学科：{{subject}}
题目内容摘要：
{{questions_text}}

配图说明：{{illustration_note}}

要求：
1. 将题目转化为故事中的任务或问题，不改变数学本质和难度。
2. 语言生动有趣，用词简单，适合儿童阅读。
3. 内容健康正面，无暴力、恐怖等不适合儿童的内容。
4. 故事长度：{{min_chars}}-{{max_chars}}字。
5. 结构分为四段：开头（引入角色）→ 发展（遇到题目/挑战）→ 高潮（思考与解决）→ 结尾（总结或收获）；每段尽量有清晰可画的场景，便于对应上述 {{panels_per_prompt}} 组插图。
6. 在故事末尾可加一行【学习要点】列出本故事涉及的知识点（简短 bullet）。

请直接输出故事正文，不要输出"故事："等前缀。
```

**变量说明**：
- `illustration_note`：由配置拼出。若 `panels_in_image` 与 `panels_layout` 存在，则为「本故事将配图：共约 N 组插图，每组插图为多格连环画（6 格，布局 2x3…）」。若 `include_dialogue` 为 true 追加「插图中可包含人物对话或旁白」；否则追加「插图中不绘制对话框或旁白文字…」。

### 输出

- **story**：故事正文字符串
- **theme**：主题（来自兴趣匹配）
- **character_name**：主角名
- **illustration_prompts**：由节点 2 根据 story 生成（见下）

---

## 三、节点 2：插图提示生成

**作用**：将故事正文按段落/句子拆成多段，用 LLM 为每段生成一句 20～50 字的插图描述。

### 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| story | string | 故事正文（来自节点 1） |
| theme | string | 主题 |
| character_name | string | 主角名 |
| max_prompts | int | 最多几条描述，默认 5 |

### 提示词模板（完整）

```
你是一位儿童插画描述助手。根据以下故事片段，为每一段写一句插图描述（用于 AI 绘图或插画师参考）。

要求：
1. 风格：儿童漫画，色彩鲜艳，适合 3-12 岁。
2. 主题：{{theme}}，主角名为 {{character_name}}。
3. 每句描述 20-50 字，包含场景和角色动作。
4. 直接输出多行，每行一句描述，不要编号和多余说明。

故事片段：
{{segments}}
```

**预处理**：将 `story` 按 `\n\n` 或 `。！？` 拆分，取每段长度 >10 字的前 `max_prompts` 段，用换行拼成 `segments`。

### 输出

- **illustration_prompts**：字符串数组，每项为一句中文插图描述。

---

## 四、节点 3：英文绘图提示词优化（LLM）

**作用**：把单条中文插图描述改写成一条英文绘图模型可用的提示词（含风格、分镜、角色一致性等）。

### 输入参数

| 参数 | 类型 | 说明 |
|------|------|------|
| raw_prompt | string | 中文插图描述（来自节点 2 的一条） |
| style | string | children / anime / cartoon / line_art |
| line_art | bool | 是否黑白线稿 |
| panels_hint | string | 如 "6 格连环画，布局 2x3" 或 "单幅" |
| reference_hint | string | 参考图说明（仅 Midjourney 时非空） |
| prompt_template | string | 可选，如 "[manga style], [scene description]..." |
| panels_in_image | int | 单张图内分镜数，如 6 |
| panels_layout | string | 如 "2x3" |
| include_dialogue | bool | 是否含对话框/旁白 |
| character_interest | string | 兴趣角色，如 "奥特曼" |
| provider | string | ttapi_midjourney / gemini |

### 配置与风格映射

- **style_desc**（按 style / line_art）：
  - children：`children's illustration, cute, colorful, suitable for 3-12 years old`
  - anime：`anime style, Japanese animation, clean lines, vibrant colors`
  - cartoon：`cartoon style, Western cartoon, expressive characters`
  - line_art：`black and white line art only, no color, clean outline drawing`
- **engine_label**（按 provider）：Midjourney image generation / Gemini image model

### 提示词模板（完整，含条件段落）

```
你是一位 AI 绘图提示词助手。根据「图片生成需求配置」将下面的中文插图描述改写成一句英文 {{engine_label}} 可用的提示词。

要求：
1. 输出仅一句英文，不要编号、不要解释。
2. 风格要求：{{style_desc}}
3. 画面：{{panels_hint}}，适合儿童观看，无暴力恐怖。
4. 保留场景与角色动作的核心含义，保证角色一致性与场景连贯性。
{{#if reference_hint}}5. 参考说明：{{reference_hint}}{{/if}}
{{#if panels_in_image && panels_layout}}6. 多格分镜：单张图内包含 {{panels_in_image}} 格连环画，布局 {{panels_layout}}（如 2x3 即两行三列），参考中国传统寓言连环画（如郑人买履）的构图与分镜方式。{{/if}}
{{#if include_dialogue}}7. 每格内需有个性化人物对话或场景对话：在描述中体现对话框、旁白或角色说的话，使画面有故事感。
8. 若存在对话框或人物对白，请先将对白内容用简体中文准确表述，再据此生成英文提示词中的对话与表情描述，不要直接生造英文台词。{{/if}}
{{interest_instruction}}
{{panel_instruction}}
{{template_instruction}}

中文描述：
{{raw_prompt}}

直接输出一句英文提示词：
```

**interest_instruction**：若 `character_interest` 非空，则为「主角/角色设定（必须遵守）：本次指定兴趣爱好为「{{character_interest}}」。请根据该兴趣生成…并在所有分格中保持该角色一致。」否则为通用角色一致性说明。

**panel_instruction**：若 `include_dialogue` 为 true，要求按 Panel 1/2… 描述每格画面与对话；若为 false，要求画面中不要出现对话框/旁白，且每格下方预留较高空白横条。

**template_instruction**：若配置了 `prompt_template`，则追加一段「输出格式要求…」和模板内容。

### 输出

- **refined_english_prompt**：单条英文绘图提示词字符串。

---

## 五、节点 4：调用绘图 API

**作用**：用节点 3 输出的英文提示词调用 TTAPI（Gemini 或 Midjourney），得到图片 URL。

### 4.1 TTAPI Gemini

- **接口**：`POST https://api.ttapi.io/gemini/image/generate`
- **Headers**：`TT-API-KEY`、`Content-Type: application/json`
- **Body 参数**：

| 参数 | 类型 | 必填 | 说明 |
|------|------|------|------|
| prompt | string | 是 | 英文提示词（节点 3 输出） |
| mode | string | 是 | gemini-2.5-flash-image-preview / gemini-3.1-flash-image-preview 等 |
| aspect_ratio | string | 否 | 9:16 / 16:9 / 1:1 等 |
| image_size | string | 否 | 1K / 2K / 4K（部分模型生效） |
| google_search | bool | 否 | 是否启用谷歌搜索 |
| thinking_level | string | 否 | Minimal / High（部分模型） |
| refer_images | array[string] | 否 | 垫图 URL 列表 |

- **响应**：`data.image_url` 为单张图 URL。

### 4.2 TTAPI Midjourney

- **提交**：`POST .../midjourney/v1/imagine`，body：`{ "prompt": "... --cref <参考图URL> --v 6.0", "mode": "fast", "timeout": 300 }`
- **轮询**：`POST .../midjourney/v1/fetch`，`{ "jobId": "..." }`，直到返回 `data.images`。

### 4.3 在 Coze 界面中的配置位置（config 对应关系）

`coze-workflow-图片生成.json` 里节点 4 的 **config** 对应在 Coze 画布中的配置方式如下（以「HTTP 请求」或「自定义 API」节点为准，具体以 Coze 当前产品界面为准）：

| JSON config 字段 | Coze 中的位置 | 说明 |
|------------------|---------------|------|
| `config.gemini.url` | 该节点的 **「请求 URL」/「URL」** | 填 `https://api.ttapi.io/gemini/image/generate` |
| `config.gemini.method` | 该节点的 **「请求方法」** | 选择 **POST** |
| `config.gemini.headers` | 该节点的 **「请求头」/「Headers」** | 添加 `Content-Type: application/json`；`TT-API-KEY` 不要写死，在 Coze **工作流/机器人的「环境变量」或「密钥管理」** 里配置 `TTAPI_API_KEY`，在此处用变量引用（如 `{{env.TTAPI_API_KEY}}` 或平台提供的密钥变量） |
| `config.gemini.body_keys` + `gemini_mode` 等 | 该节点的 **「请求体」/「Body」** | 选择 **JSON**，按 body 键填：`prompt`（来自上游「英文绘图提示词优化」节点输出）、`mode`、`aspect_ratio`、`image_size`、`google_search`、`thinking_level`、`refer_images`；后几项可填固定值（对应 JSON 中的 `gemini_mode`、`gemini_aspect_ratio` 等）或工作流变量 |

总结：**URL、Method、Headers、Body** 都在「调用绘图 API」这一节点的配置面板里；**API Key** 在 Coze 的**环境变量/密钥**中配置，再在请求头里用变量引用。

### 配置参数（来自 content_generation.yaml illustration 段）

- provider、style、line_art、panels_per_prompt、panels_in_image、panels_layout、include_dialogue、reference_image_url
- Gemini：gemini_mode、gemini_aspect_ratio、gemini_image_size、gemini_google_search、gemini_thinking_level、gemini_refer_images

## 六、在 Coze 中搭建建议

1. **节点 1**：使用「大模型」节点，系统提示/用户提示填入上述「故事生成」提示词，输入变量：child_profile、questions、subject；输出解析为 story、theme、character_name（可从兴趣与 child_profile 推导）。
2. **节点 2**：使用「大模型」节点，提示词用「插图提示生成」模板，输入 story、theme、character_name；输出解析为多行文本再拆成数组 illustration_prompts。
3. **节点 3**：对每条 illustration_prompts 循环，每个循环内一个「大模型」节点，提示词用「英文绘图提示词优化」模板，输入 raw_prompt 与配置项；输出 refined_prompt。
4. **节点 4**：使用「HTTP 请求」或「代码」节点，根据 provider 调用 TTAPI Gemini 或 Midjourney，传入上一步的 refined_prompt 与配置中的 mode、aspect_ratio 等。

将本文档与同目录下 `coze-workflow-图片生成.json` 配合使用：JSON 中给出各节点 id、name、prompt 占位与参数列表，便于在 Coze 中逐节点创建或与官方导入格式对齐后导入。
