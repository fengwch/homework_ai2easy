# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Backend is the Go (Kratos v2) main service for the children's homework tutoring app. It owns user/child/assignment business logic, persistence (MySQL + Redis), authentication (JWT + WeChat + SMS), file uploads, and orchestration of the Python AI service (`agent/`). It exposes both gRPC and HTTP from the same proto definitions; the HTTP variant is what the uni-app frontend consumes.

## Common Commands

### Bootstrap (first time only)

```bash
make init          # install protoc plugins (kratos / wire / proto-gen-*)
make api           # generate Go + go-http + go-grpc + openapi from api/**/*.proto
make wire          # regenerate cmd/server/wire_gen.go
```

### Build / Run

```bash
make build         # full build (regenerates api + wire)
make build-fast    # incremental, skip api & wire regen
make run           # run with -conf configs/config.yaml
make dev           # run with -conf configs/config.dev.yaml
go run ./cmd/server -conf configs/config.yaml   # raw equivalent
```

### Tests

```bash
make test          # all
make test-unit     # internal/biz/usecase + internal/pkg only
make test-api      # test/  (integration / API suite, may need MySQL+Redis up)
make test-short    # `go test -short ./...`
```

Single test file:
```bash
go test ./internal/biz/usecase -run TestUserUsecase_Profile -v
```

### Tidy / Clean

```bash
make tidy          # go mod tidy + go fmt
make clean         # rm bin/ dist/
```

### Pack for deploy

```bash
make pack          # build → dist/<service>.tar.gz with configs + scripts
```

### Default ports

- HTTP: `0.0.0.0:8000` (default in `cmd/server/main.go`)
- gRPC: `0.0.0.0:9002` (current `configs/config.yaml`; **note** Kratos default flag is `:9000`)
- AI agent upstream: `http://0.0.0.0:8001` (Python service from `agent/`)

## Architecture

### Layered request flow

```
HTTP / gRPC client
   ↓
internal/server         (HTTP & gRPC server bootstrap, middleware)
   ↓
internal/service/grpc   (proto-generated server interface impl; thin adapter)
   ↓
internal/biz/usecase    (business logic; depends only on interfaces)
   ↓
internal/data           (repository impl; MySQL via GORM, Redis, AI agent client)
```

Wire (`cmd/server/wire.go` → `wire_gen.go`) injects from data → biz → service → server.

### `api/` — proto-first

One folder per business domain: `auth/`, `user/`, `child/`, `assignment/`, `content/`, each under `<domain>/v1/<domain>.proto`. Every RPC carries a `google.api.http` annotation:

```proto
rpc Login (LoginRequest) returns (LoginResponse) {
  option (google.api.http) = { post: "/api/v1/auth/login" body: "*" };
}
```

`make api` regenerates:
- `<domain>.pb.go` — message types
- `<domain>_grpc.pb.go` — gRPC server / client
- `<domain>_http.pb.go` — Kratos HTTP server / client (this is what makes HTTP work without writing handlers)
- `openapi.yaml` (project root) — Swagger spec served at `/q/swagger-ui` (`internal/server/http.go`)

**Never write HTTP handlers by hand.** The proto annotation IS the route. Adding/changing a route always means: edit proto → `make api` → implement the new method on the service.

### `internal/service/grpc/` — proto adapter

Each service implements the `<Domain>HTTPServer` interface generated by Kratos. Compile-time assertion at the top of each file enforces signature matching:

```go
var _ v1.AuthServiceHTTPServer = (*AuthService)(nil)
```

If this line fails to compile, the proto is out of sync with the implementation — regen, don't paper over.

Service methods are **thin**: parse request → call usecase → map result/error to response. No business logic, no SQL, no external HTTP.

Five services live here today:

| Service | Proto | Routes (HTTP prefix `/api/v1/...`) |
|---|---|---|
| `AuthService` | `api/auth/v1/auth.proto` | `auth/{send-sms, login, wechat-login, password-login, register, refresh, reset-password}` |
| `UserService` | `api/user/v1/user.proto` | `user/{profile, avatar, change-password, subscription}` |
| `ChildService` | `api/child/v1/child.proto` | `children` |
| `AssignmentService` | `api/assignment/v1/assignment.proto` | `assignments/{upload, scan, ...}` |
| `ContentService` | `api/content/v1/content.proto` | (calls `agent/` for OCR / story / TTS / illustration) |

### `internal/biz/usecase/` — business logic

One file per domain (`user.go`, `auth.go`, `child.go`, `assignment.go`, `content.go`) plus `provider.go` (Wire `ProviderSet`). Usecases:

- depend only on **interfaces** declared in the same package (`UserRepo`, `AuthRepo`, ...);
- compose multiple repos / external clients;
- own all transactional and validation logic;
- never import `internal/server`, `internal/service`, or generated proto types directly — convert at the service-layer boundary.

Tests live next to them (`user_usecase_test.go`, `auth_usecase_test.go`) and use `internal/testutil` (miniredis, FakeUserRepository, etc.) to stay hermetic.

### `internal/data/` — repository implementations

Implements the interfaces declared in `biz/usecase`. Hosts:

- GORM models + queries against MySQL (`smartstudy`).
- Redis client (verification codes, sessions, rate limits).
- AI agent HTTP client (delegates to `internal/pkg/aiagent`).
- File upload helpers (delegates to `internal/pkg/upload`).

Wire `ProviderSet` in `internal/data/provider.go`. Data structs are local — never leak into usecase signatures; map to biz domain types.

### `internal/server/`

- `http.go` — `NewHTTPServer(*conf.Server, log.Logger, *jwt.JWT, AuthService, UserService, ChildService, AssignmentService, ContentService, *biz.ContentUsecase, *redis.Client) *http.Server`. Wires middleware (recovery, CORS conditionally on `c.Cors.GetEnabled()`, `JWTAuthMiddleware`, `MultipartAwareRequestDecoder`), mounts `/uploads/` static, registers all 5 `RegisterXxxServiceHTTPServer`, and serves Swagger UI from `docs/api/openapi.yaml`.
- `grpc.go` — gRPC counterpart, fewer middleware (no CORS, no JWT — that's HTTP-only by design; gRPC is for trusted internal callers).

### `internal/conf/`

Bootstrap proto schema (`conf.proto`) + generated `conf.pb.go`. `cmd/server/main.go` loads `configs/config.yaml`, decodes into `conf.Bootstrap`, then passes sub-configs to providers via Wire. **Don't** read raw YAML in business code — go through the typed `*conf.Server` / `*conf.Data` / `*conf.Logger` values that providers accept.

### `internal/pkg/` — shared utilities (no business logic)

| Package | Purpose |
|---|---|
| `aiagent` | HTTP client for the Python `agent/` service (OCR, story, TTS, illustration) |
| `apilist` | Static catalog of registered routes for `/api/list` |
| `ctxkey` | Strongly-typed `context.Context` keys (user_id, child_id, ...) |
| `errors` | Project-wide error codes and `kerrors.Error` constructors |
| `jwt` | Token sign/verify + `JWTAuthMiddleware` |
| `logger` | Zap + lumberjack + Kratos `log.Logger` adapter (see "Logging" below) |
| `password` | bcrypt helpers |
| `pdf` | PDF generation (assignment exports, etc.) |
| `sms` | SMS provider abstraction (Aliyun / mock) |
| `upload` | File upload validation + storage |
| `wechat` | WeChat MP login / payment helpers |

Internal packages are allowed to depend on `internal/conf` but **must not** depend on `internal/biz`, `internal/data`, `internal/service`, or `internal/server`.

### Logging

- Acquire a logger via Wire-injected `*log.Helper` derived from `pkg/logger`. **Never** call `log.New`, `zap.New*`, or configure a root handler in business code.
- Always attach the request context: `helper.WithContext(ctx).Infow("event", "key", val)` so trace IDs propagate.
- File rotation, console mirroring, level, format, and stack traces are configured via `LoggerConfig` in `configs/config.yaml`:
  ```yaml
  logger:
    level: info        # debug|info|warn|error
    format: json       # json|console
    output: both       # console|file|both
    file_path: logs/app.log
    max_size: 100      # MB
    max_backups: 7
    max_age: 30        # days
    compress: true
    enable_caller: true
    enable_stacktrace: true   # error+ frames
  ```

### Error codes

Six fixed ranges (see `internal/pkg/errors`):

| Range | Class |
|---|---|
| 10000-19999 | system / infrastructure |
| 20000-29999 | business |
| 30000-39999 | auth |
| 40000-49999 | parameter validation |
| 50000-59999 | external dependency |
| 60000+ | reserved |

Construct via `errors.New(code, reason, message)`. The HTTP layer maps these to status + body automatically.

## Configuration

Layering: `configs/config.yaml` defaults ← env override (Kratos config supports env interpolation) ← per-flag `-conf` path.

Notable knobs (current `configs/config.yaml`):
- `server.http`: 8000, `server.grpc`: 9002
- `api_base_url`: `https://hw.gameyeah.net` (used to build absolute upload URLs)
- MySQL: `root:root@tcp(127.0.0.1:3307)/smartstudy`
- Redis: `127.0.0.1:6379`
- JWT expiry: 30 days
- `ai_agent.endpoint`: `http://0.0.0.0:8001`, `timeout`: 600s (long enough for illustration jobs from `agent/`)
- WeChat MP: `wx134d3e0f3c33eb77` + secret (**production secret currently lives in `configs/config.yaml` — must be moved to env or a secret manager before any external deploy**; see `memory-bank/5-decision-log.md`)
- SMS: provider `mock` by default (`internal/pkg/sms`)

When adding env vars, update `.env.example` (if present) **and** the `Bootstrap` proto schema; Kratos will not bind a field that isn't declared in `conf.proto`.

## Testing layout

| Path | Scope |
|---|---|
| `internal/biz/usecase/*_test.go` | unit; uses `internal/testutil` (miniredis + fake repos), no network |
| `internal/pkg/*_test.go` | utility unit tests |
| `test/` | integration; spins real HTTP server + miniredis + sqlite-or-mysql; requires more setup |
| `make test-api` | runs `test/` |

Conventions:
- mock at the **interface boundary** (your own repo / client interfaces), not deep inside third-party SDKs.
- Bug fixes start with a failing test that reproduces, then the fix.
- Don't touch `~/.gitconfig` test repos; everything stays under `test/`.

## Forbidden / load-bearing constraints

These mirror `.cursorrules` and the `memory-bank/`. Violations require an explicit decision-log entry.

- **No hand-written HTTP handlers.** Every route comes from a proto + `google.api.http` annotation; if you find yourself writing `s.HandleFunc(...)`, stop and add the proto.
- **No business logic in `internal/service/grpc/`.** It's an adapter layer.
- **Service layer must keep `var _ v1.XxxServiceHTTPServer = (*XxxService)(nil)` compile-time assertion.** Don't delete to "fix" a build break — regen instead.
- **No direct GORM access in `biz/usecase/`.** Go through the repo interface.
- **No raw `log.Println` / `fmt.Println` for events.** Use the injected `*log.Helper` with `WithContext(ctx)`.
- **No hardcoded secrets / endpoints.** Read from `*conf.*` types loaded by Kratos config.
- **No new dependencies that duplicate existing functionality** (another HTTP framework, another logger, another ORM). Extend pkg/ if needed.
